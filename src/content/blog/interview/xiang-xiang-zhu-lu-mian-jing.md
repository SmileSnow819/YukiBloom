### 面试内容

1. 做一下自我介绍
2. Data Agent 是阿里开源项目，你在里面是参与贡献吗？
3. 该开源项目的维护组织构成是怎样的？除阿里员工外是什么人在维护？
4. 当时做 Data Agent 项目时，小组人员构成是怎样的？
5. B 站实习 8 月开始，才一个多月，想要换实习团队的原因是什么？
6. 当前这份实习没有转正机会吗？
7. 经历过多家大厂实习，你后续对于实习、转正机会，倾向什么样的团队？
8. B 站的 Agent 效能分析平台，最终展示、分析的数据是什么？
9. Agent 效能分析平台是通过什么方式拿到 Agent 请求、状态等原始数据的？
10. 你个人后续的技术方向规划是什么？
11. 你刚才提到“不需要后端”的项目，具体是什么含义？

## 面试复盘总结

### 1. 这场面试重点考察什么

这轮面试除了考察项目技术深度，也比较关注候选人的稳定性、职业规划和面对不确定需求时的推进能力。问题主要集中在：

- Data Agent 开源项目的真实参与程度和团队协作方式。
- B 站 Agent 效能分析平台的数据来源与最终价值。
- 前端背景如何向 AI 应用、后端和更完整的工程能力扩展。
- 面对模糊需求、线上问题和历史重构时，能否做出合理判断。

### 2. 模糊需求如何推进

只有“把网站改造成类似 Codex 插件”的想法时，不应该直接开始写代码，可以按下面的步骤推进：

```text
明确目标 -> 确认用户场景 -> 拆出最小可行版本 -> 评估技术方案 -> 排期验证 -> 迭代扩展
```

先确认插件解决什么问题、服务哪些用户、运行在哪个平台，以及成功标准是什么。然后把需求拆成最小闭环，例如先完成安装、核心交互和一个可验证的使用场景，再评估权限、通信、兼容性和发布方式。工期不确定时，可以先做短周期技术 Spike，用真实结果替代猜测。

### 3. 三件事并行如何排优先级

一般可以按照影响范围和紧急程度排序：

1. 线上大量用户反馈 Bug：优先处理，避免继续影响用户和业务数据。
2. 插件新需求：确认是否有明确业务承诺，再拆分出可以独立交付的部分。
3. 旧框架重构：除非已经影响线上稳定性，否则安排在风险可控的窗口推进。

可以使用“影响范围、紧急程度、投入成本、依赖关系”四个维度评估，并及时和产品、业务方同步取舍。重构不应和线上救火争抢同一批资源，也不应该因为新需求不断出现而完全没有边界。

### 4. Agent 效能平台如何衡量

Agent 效能平台通常需要记录请求、任务、工具调用、模型响应、耗时、Token、错误和最终结果等数据。展示层可以围绕这些指标分析：

- 调用量、活跃用户和任务完成量。
- Agent 任务成功率、失败原因和重试次数。
- 工具调用次数、耗时、错误率和人工接管率。
- 输入输出 Token、单次任务成本和响应时延。
- 不同模型、团队或项目的使用效果对比。

关键是把“使用了多少”与“产生了什么效果”区分开。调用次数增加不一定代表效率提高，还需要结合交付周期、人工修改量、缺陷率和一次成功率判断实际收益。

### 5. Data Agent 项目如何说明个人贡献

介绍开源项目时，需要清楚区分项目整体能力、团队贡献和个人负责范围。可以从项目背景、技术架构、自己负责的模块、遇到的问题和最终效果展开，避免把整个项目的能力都归到个人身上。

如果被追问维护组织，也可以说明开源项目通常由核心维护者、企业员工、社区贡献者和使用方共同维护，贡献形式包括代码、Issue、文档、测试、示例和问题反馈。项目价值不仅在于写了多少代码，也在于是否降低了数据分析门槛、沉淀了可复用能力和帮助其他团队接入。

### 6. 面试准备提醒

这类面试需要同时准备技术和职业问题：

- 能用几分钟讲清楚一个完整项目。
- 能说明自己为什么换实习，以及希望进入什么样的团队。
- 准备至少一个模糊需求推进案例和一个优先级取舍案例。
- 对 AI 项目的数据来源、指标口径和最终价值有明确回答。
- 诚实说明前端、后端、Agent 和大模型方面的能力边界与补强计划。
