## 面试复盘总结

### 1. 一面重点

这轮面试围绕三条主线展开：

1. **Data Agent 项目深度**：项目背景、数据接入、Text-to-SQL、上下文治理和个人贡献。
2. **AI 辅助开发能力**：代码索引是否能被 Codex、Cloud Code 等工具消费，以及 AI 生成代码为什么需要重构和验证。
3. **全栈基础**：Agent 原理、SSE 会话管理、Java/Go 后端接触情况和前端工程基础。

### 2. Data Agent 怎么讲

介绍 Data Agent 时，不要只说“用户提问后生成 SQL”。更完整的链路是：

```text
自然语言问题 -> 意图识别 -> 语义层映射 -> SQL 生成 -> 安全校验 -> 数据查询 -> 图表或文本回答
```

其中语义层负责把业务概念映射到真实的数据表、字段和指标，避免模型只根据字段名猜测。生成 SQL 后还需要进行只读限制、权限校验、参数校验、超时控制和错误修正，不能让模型输出直接无保护地执行。

### 3. AI 上下文治理

Data Agent 或代码 Agent 的上下文治理，核心是让模型在正确的时间读取正确的信息：

- 按任务筛选相关模块、数据表、字段和业务规则。
- 将模块 README、代码索引、接口定义和历史决策作为结构化上下文。
- 区分长期规则、当前任务信息和临时执行结果。
- 控制上下文大小，减少无关内容和重复内容。
- 记录模型调用、工具调用和最终结果，便于复盘和评测。

上下文治理的目标不是让模型读得越多越好，而是在成本、完整性和准确性之间取得平衡。

### 4. SSE 中断与会话处理

上一条 SSE 请求未结束时，用户又发送新消息，需要先明确会话和请求的身份：

```text
conversationId -> messageId -> requestId -> AbortController
```

新请求到达后，可以由前端通过 `AbortController` 取消旧请求，服务端也根据 `requestId` 或版本号拒绝旧请求继续写入当前会话。每个事件应携带会话 ID、消息 ID、序号和结束状态，前端只接收当前会话、当前请求版本的事件，避免旧响应覆盖新消息。

### 5. 前端基础追问

Webpack 与 Vite 的对比可以从开发体验和构建机制回答：Webpack 在大型项目、复杂 Loader/Plugin 体系和成熟生态上仍然有优势；Vite 开发阶段基于原生 ESM，按需编译，启动和热更新更快，生产构建再交给 Rollup 等工具处理。选择时需要结合项目规模、生态兼容性和团队迁移成本。

Promise、`async/await` 的错误处理需要覆盖同步异常、异步拒绝和请求取消：使用 `try/catch` 捕获 `await` 错误，必要时在 Promise 链末尾统一处理，并区分业务错误、网络错误、超时和主动取消，避免所有错误都被当成普通失败提示。
