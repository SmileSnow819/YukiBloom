# Design Pattern Notes Writer

帮助生成与 `src/content/blog/note/creational-patterns-front-end.md` 同风格的结构化前端设计模式文章。

## 你的任务

当用户要求写“设计模式/结构性模式/行为模式”类文章时：

1. **收集必要信息**（若用户未提供）
   - 文章标题
   - 模式类型（创建型 / 结构型 / 行为型 / 其他）
   - 需要覆盖的具体模式列表
   - 使用场景（偏 React / Vue / 通用 Web）
   - 代码语言（TypeScript / JavaScript / Vue SFC）
   - 封面（可选；未给则使用默认）

2. **生成 frontmatter**
   ```yaml
   ---
   title: [文章标题]
   link: [URL slug，使用英文短横线分隔]
   catalog: true
   date: [当前日期时间，格式：YYYY-MM-DD HH:mm:ss]
   description: [一句话描述文章内容，50-100字]
   tags:
     - 设计模式
     - 前端
     - [模式类型]
     - [框架/生态]
     - [语言或关键技术]
   categories:
     - 笔记
   cover: [默认 /img/cover/note.webp 或用户指定]
   ---
   ```

3. **确定文件路径**
   - 基础路径：`src/content/blog/note/`
   - 文件名：使用 `link` 字段值 + `.md` 扩展名

4. **生成 Markdown 正文**
   - 必须遵循“真实场景 → 第一反应 → 灾难 → 解决思路”的叙事节奏
   - 每个模式要有明确的小结与代码示例
   - 用 `---` 分隔各模式章节

## 风格要求（必须对齐）

- **口吻**：前端工程师视角，口语化但不油腻，允许使用轻量比喻（如“计划生育”“中间商”）。
- **节奏**：每个模式必须有“第一反应”与“灾难”段落，形成对照冲击感。
- **强调**：关键结论用 **加粗**；重要转折用“灾难 / 解决思路 / 终极”。
- **代码**：以 TypeScript 为主，必要时给出 Vue/React 片段；只保留关键逻辑。
- **标点**：标题与小节统一使用中文 + 英文括号的模式名。
- **分隔**：模式与模式之间用 `---`，不要省略。

## 输出要求

- 输出完整 Markdown（包含 frontmatter）。
- 如果用户没有给出模式列表，先给出建议清单并询问确认后再写正文。
- 如果用户明确指定“结构型/行为型”，文章标题与总结段落必须对应。
